A security lead may say this, and the controls are real. A company may route every AI call through a proxy, or point its AI desktop app at the company's own cloud account. Each answers a real question. Each leaves two open: what is inside the call, and what the work does once it leaves the person's machine. A proxy is a server between people's machines and the internet that decides which services they may reach.

A proxy that checks only where a call goes has no rule about what is in it

A proxy with a list of approved services would stop the service rep's personal tool and the seller's unknown one. It would not stop the support engineer. Her service was on the list, so a customer's records went to an allowed service and the proxy passed the call. The control did what it was built to do.

It gets worse where people are inventive. In an example we have seen, but not measured, people asked the tool to launch a browser and pull information out of a production system. The assistant opens a browser on the person's laptop, signs in with their own login, reads the data, and sends it to an AI service the proxy allows. The proxy never sees the trip to the production system.

While people can reach production data from their laptops, the proxy guards the call and not the source.

"Our data-loss prevention inspects what goes out"

Data-loss prevention is a real control, and it answers a different question from the proxy: it looks at content leaving through the channels it monitors and matches it against patterns or labels it knows.

It leaves three things open. Channels it does not monitor, such as a personal device. Data it does not recognize as sensitive: in the browser example above, it sees the records only on their way to the AI service, and catches them only if it recognizes them. And it gives no shared place for the work, so reuse does not start. Both paragraphs are our reasoning about the category, not a claim about any product.

Pointing the desktop app at your own cloud covers the model call, not the work

This second answer is a good one. Anthropic's page on Claude Desktop with a third-party provider, read 2026-11-20, says Claude Desktop can send all its model calls to a cloud provider the company configures, such as Amazon Bedrock or Microsoft Foundry. That governs which provider takes the model calls, while the app stays in the managed setup. Three things stay where they were:

  • The work stays on one machine. The same page says conversation history is stored on the person's device. The page someone built still reaches colleagues as a picture in a slide, so reuse does not start. Claude's own sharing does not fill the gap: Anthropic's admin guide for artifacts, read 2026-11-20, says artifacts are unavailable on third-party cloud platforms.
  • The laptop still reaches production data. The browser example works the same way. What reaches the model is better governed. What leaves the production system is not.
  • The setting covers one app. The page also says a person can leave the managed setup by signing in to claude.ai, unless the device profile restricts it. Other assistants on the same machine have settings of their own.

The passwords sit in files on laptops

Apps people build with AI need passwords and keys to reach data. In our experience they usually sit in a plain text file next to the app, and people building their first app probably do not know to put them anywhere else. The file goes wherever the folder goes: a backup, a shared drive, a zip sent to a colleague. No proxy or desktop setting looks there.

What closes the gap

Lock down access to production data so that AI work reaches it only from inside an environment built for AI work. Then a laptop has no path of its own to the production system. That holds only once workstation access to production data is actually removed. Until it is, the browser trip in the figure is still open.

One limit stays: a page a person can open on their own screen, a shared one included, can still be read by their assistant or pasted into one. That stays with your rules, which step 1 of the path starts with.

What this means for you

Keep the controls. Do not read them as the whole answer. The question from the first page is the test: if anyone can reach customer data in a production system from a laptop, the proxy is guarding the call and not the source.
