Governed engineering platform: requirements and options

A reference pattern for a governed engineering platform: the requirements it has to meet, numbered, and for each part of the platform the cloud services, catalog products and parts built in-house that can fill it.

Use this page to look things up. A list of requirements says what a platform has to do; it does not say how to build one, in what order, or whether to.

R9. Fact and decision layer

NumberRequirementKindOptions
R9.1Each Definition declares its sources: an external source or another Definition's Facts. A source carries a contract stating its known defects and normalization rules, and a join that returns nothing is an error, not an empty result.Fact sources and lineage
R9.6When a named set of Facts holds for an anchor and a period, the declared Actions run.
R9.7An outcome is data (a new Fact) or an action (a tool call, agent task, workflow, work item or notification). Actions are versioned separately, and every Action run is recorded with who acted, under which identity, against which versions and with which context.Actions and approval stages
R9.9Owners state sources, rule and outcome in plain language and an agent may draft the Definition. Before approval, a dry run replays recorded snapshots and shows which Facts and Actions would change, and the owner's approval is the version record.Definition engine
