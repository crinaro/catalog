The readings behind this page

Our summary of the vendor's pages as of the dates shown on each line (2026-10-20 to 2026-10-24); confirm on the vendor's page.

One sentence naming both a local and a cloud path

  • Open WebUI's home page says it can connect to Anthropic, OpenAI, Ollama or any service compatible with those, and that it can run on your own machine, in the cloud, or both. (openwebui.com page, read 2026-10-20)

Models from different providers in one session

  • In a Multi-Model Chat, the customer's prompt is sent simultaneously to two or more models that were selected. (docs.openwebui.com page, read 2026-10-21)

What a local model must meet

  • Open WebUI's Ollama guide says Native function calling puts tool schemas into the prompt, so with 2048 tokens of context the model can run short of room and return an empty reply or unprocessed tool-call JSON instead of calling the tool. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's agentic search page says its agentic web search depends on a model with reliable tool calling. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's agentic search page says unlocking its agentic web search features needs native tool calling in the model, plus reasonable multi-step reasoning. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's Ollama guide says switching on the num_ctx control fills in 2048, a very small figure, so a model is easily capped at 2048 tokens, even once OLLAMA_CONTEXT_LENGTH has been raised on the Ollama side. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's Ollama guide says that from Ollama v0.15.5 the default context length is picked from available VRAM: 4096 under 24 GiB, 32768 for 24 up to 48 GiB, and 262144 for 48 GiB or more. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's agentic search page names three local models, Qwen 3.6 27B, Muse Glimmer 30B and Gemma 4 31B, that clear its minimum bar for agentic search, each verified at the time of writing. (docs.openwebui.com page, read 2026-10-23)

Plan, policy and billing

  • Open WebUI's features page lists restricting model access to chosen users or groups. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's settings page says Admin Settings govern the whole instance, covering API connections, toggles for features, security policies and default behaviors. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's settings page says users cannot turn on for themselves a feature that an admin has disabled globally. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's settings page says that when an admin has turned on Direct Connections, a user can add personal API keys under User Settings, then Connections. (docs.openwebui.com page, read 2026-10-23)

A separate model for planning and for doing

  • Open WebUI's task models page says its Tasks settings hold two model pickers for background work, both defaulting to the chat's own model. (docs.openwebui.com page, read 2026-10-23)
  • Open WebUI's task models page says context compaction has its own model picker, which defaults to the current model. (docs.openwebui.com page, read 2026-10-23)

About the product

  • Open WebUI's README describes Open WebUI as a self-hosted AI platform designed to run entirely offline. (github.com page, read 2026-10-24)
