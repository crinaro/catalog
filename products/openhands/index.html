OpenHands

An open-source coding agent that plans and executes multi-step changes using terminal, browser, and code-editing tools, available for local or self-hosted deployment.

The readings behind this page

Our summary of the vendor's pages as of the dates shown on each line (2026-10-19 to 2026-10-24); confirm on the vendor's page.

Local models

  • OpenHands's LLM page names SGLang, vLLM, LM Studio and Ollama as examples of local model servers. (docs.openhands.dev page, read 2026-10-20)

Cloud models

  • OpenHands's LLM overview page has, after a short introduction, a table of access options under the heading Choose a Model Configuration Path; its first row, under the column I have, lists a key issued by a model provider or by OpenHands. (docs.openhands.dev page, read 2026-10-20)

One sentence naming both a local and a cloud path

  • OpenHands executes both proprietary and open-weight models, including Kimi, DeepSeek, and Qwen, across local, cloud, or VPC environments. (www.openhands.dev page, read 2026-10-20)

Models from different providers in one session

  • OpenHands' LLM settings page says LLM profiles suit using different models for different tasks, such as a faster model for simple work and a more powerful one for complex reasoning. (docs.openhands.dev page, read 2026-10-23)
  • OpenHands' SDK model routing page describes a built-in MultimodalRouter that sends requests that hold only text to a secondary LLM, and image-bearing requests to the primary LLM. (docs.openhands.dev page, read 2026-10-23)

Several endpoints, built in (no proxy)

  • OpenHands allows saved LLM profiles to simplify model switching, so provider settings need not be re-entered each time. (docs.openhands.dev page, read 2026-10-21)
  • OpenHands' LLM profiles page says Provider Connections let several profiles share one stored provider, key and optional base URL, each profile keeping its own model; the page limits them to local agent-server backends and hides the panel on OpenHands Cloud. (docs.openhands.dev page, read 2026-10-21)

Local and cloud in one session

  • OpenHands' LLM settings page says its LLM profiles let a user hold several LLM configurations and swap between them, even while a conversation is active. (docs.openhands.dev page, read 2026-10-21)

What a local model must meet

  • OpenHands' local model guide says running Qwen3.6-35B-A3B takes a recent GPU with 24GB or more of VRAM when running quantized variants, or several GPUs when you want full precision or bigger context windows. (docs.openhands.dev page, read 2026-10-23)
  • OpenHands' local model guide names a Mac with Apple Silicon and 64GB or more of unified memory as another way to meet its stated hardware need for quantized variants of Qwen3.6-35B-A3B. (docs.openhands.dev page, read 2026-10-23)
  • Tool-use reliability varies widely for open-weight models and local models. (docs.openhands.dev page, read 2026-10-19)

Plan, policy and billing

  • OpenHands' organization settings page says all members use the organization's LLM configuration unless they have set personal overrides. (docs.openhands.dev page, read 2026-10-23)
  • OpenHands' LLM page has an 'I have / Start here' table whose first row sends a reader who holds a key issued by a model provider, or by OpenHands itself, to the page on configuring a model in Agent Canvas. (docs.openhands.dev page, read 2026-10-19)

A separate model for planning and for doing

  • OpenHands' model recommendations advise using cheaper profiles for routine edits and then returning to a stronger model when planning, debugging or reviewing. (docs.openhands.dev page, read 2026-10-19)

About the product

  • OpenHands' README says OpenHands runs on the user's machine by default and can connect to agent backends such as Docker containers, virtual machines or a company's own infrastructure, and that agents can optionally run on OpenHands Cloud, or on the infrastructure of OpenHands Enterprise. (github.com page, read 2026-10-24)
