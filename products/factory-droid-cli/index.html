Factory (Droid CLI)

A hosted multi-agent software-delivery platform where an agent its maker calls a Droid takes a task from the terminal, an IDE, a browser or Slack and returns a code change to review.

The readings behind this page

Our summary of the maker's pages as of the dates shown on each line (2026-09-24 to 2026-10-24); confirm on the maker's page.

Models from different providers in one session

  • A Factory subagent (custom droid) has a model of its own, which it can inherit from the parent session or swap for another model tuned for the task. (docs.factory.com page, read 2026-10-22)
  • In a custom droid's model field, a BYOK custom model is named by the prefix custom: followed by the value of the model field in the user's config, for instance custom:gpt-4o-mini, and not by its display name. (docs.factory.com page, read 2026-10-22)
  • Factory's custom droids, its subagents, can inherit the parent session's model or run a different one suited to the task. (docs.factory.com page, read 2026-10-21)

Several endpoints, built in (no proxy)

  • Factory (Droid CLI) allows the customer to use their own OpenAI or Anthropic keys, or to connect to open source model providers, or to run models locally on their hardware. (docs.factory.com page, read 2026-10-22)
  • You add custom models to the customModels array in the ~/.factory/settings.json file. (docs.factory.com page, read 2026-10-22)
  • Factory (Droid CLI) lets the customer run models on their own hardware using an OpenAI-compatible server, and then point baseUrl at it. (docs.factory.com page, read 2026-10-21)

A model on your machine

  • You run models on hardware you own, using an OpenAI-compatible server, and set baseUrl to point at it. (docs.factory.com page, read 2026-10-22)

Local and cloud in one session

  • Custom Models in /model show saved models, which are labeled with their displayName. (docs.factory.com page, read 2026-10-22)
  • Factory's page says the Droid CLI and its desktop app, both of which read the local settings.json, offer personal custom models, and that these models are absent from the hosted web or mobile platforms of Factory. (docs.factory.com page, read 2026-10-22)

What a local model must meet

  • Factory's article says a good chat reply from a model endpoint does not show that it copes with tool calls, with a longer context, or with repeated exchanges. (factory.com page, read 2026-10-23)
  • Factory's custom-models page says that for a local Ollama server the context window should be raised to 32k or more, and gives starting the server with OLLAMA_CONTEXT_LENGTH=32000 as an example. (docs.factory.ai page, read 2026-10-21)
  • Model Size Consideration : Agentic coding tasks show significantly lower performance for models with under 30 billion parameters. (docs.factory.ai page, read 2026-10-21)

Plan, policy and billing

  • Enterprise Controls and Managed Settings restrict provider access, base URLs, and custom models at the org level. (docs.factory.ai page, read 2026-10-21)

A separate model for planning and for doing

  • Factory's DeepSeek article says Factory lets you switch models for each task instead of tying you to one provider. (factory.com page, read 2026-10-23)
  • Factory's GLM article says that in Missions, where an orchestrator hands work to worker and validator agents, GLM can take the worker role, set through --worker-model glm-5.2, and a stronger model can do the validation. (factory.com page, read 2026-10-23)

Works with other products

  • Factory (Droid CLI) connects to OpenRouter, Fireworks, Together AI, Ollama, and vLLM, as well as most open-source providers. (docs.factory.com page, read 2026-09-24)

About the product

  • Factory's bring-your-own-key page says the Droid CLI accepts the user's own OpenAI or Anthropic keys, can reach any provider of open-source models, and can run models on the user's own local hardware. (docs.factory.com page, read 2026-10-24)
